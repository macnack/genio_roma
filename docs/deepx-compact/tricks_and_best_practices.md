# Tricks and best practices (DX-M1 toolchain)

> Compact of docs/deepx/tricks_and_best_practices.md. Full text and extended citations are in the source file.

Pins: dx-compiler@a087726ead v2.5.0, dx-runtime@73ff9904f5 v2.5.0, dx-all-suite@51d81fe2ef v2.5.0, dx_app@375de0344f v3.3.0. `.deepx/memory/*.md` are DEEPX agent-facing files; entries tagged "(agent rule)" are agent-behaviour rules, not SDK facts.

## Officially documented facts

### Export (PyTorch -> ONNX)

- Batch 1 only: `dummy_input = torch.randn(1, 3, H, W)`; check `shape[0] == 1` on every graph input. [dx-compiler@a087726ead v2.5.0: .deepx/memory/common_pitfalls.md#L8-L25]
- Static shapes: no `dynamic_axes`; verify every input `dim_value > 0`. Several input sizes need one `.dxnn` per size. [dx-compiler@a087726ead v2.5.0: .deepx/memory/common_pitfalls.md#L78-L103]
- Opset 11-21 (DX-COM v2.5.0); opset 13 recommended. Check `onnx.load(...).opset_import[0].version`. [dx-compiler@a087726ead v2.5.0: .deepx/memory/common_pitfalls.md#L107-L131]
- Call `model.eval()` before export (training mode changes BatchNorm/Dropout topology). [dx-compiler@a087726ead v2.5.0: .deepx/agents/dx-model-converter.md#L29-L47]
- Descriptive `input_names` must match the config.json `inputs` key. Validate with `onnx.checker.check_model`; assert a single output for Ultralytics YOLO. [dx-compiler@a087726ead v2.5.0: .deepx/agents/dx-model-converter.md#L49-L72]
- Official export call: `torch.onnx.export(model, dummy_input, "model.onnx", opset_version=13, input_names=["images"], output_names=["output0"], dynamic_axes=None)` with `dummy_input = torch.randn(1, 3, 640, 640)`. [dx-compiler@a087726ead v2.5.0: .deepx/agents/dx-model-converter.md#L49-L62]
- Do NOT run onnx-simplifier automatically (FP32 rounding from constant folding, lost node names, possible graph breakage, renamed inputs mismatching config.json). Flow: Export -> Validate -> Compile. If the user asks, re-check the input name. [dx-compiler@a087726ead v2.5.0: .deepx/memory/common_pitfalls.md#L212-L247] (agent rule)
- Ultralytics YOLO only: manual `torch.onnx.export` yields 6 outputs unless `Detect.export=True`. Prefer `model.export(format="onnx", ...)` or `yolo export model=... format=deepx` (x86-64 Linux, detection only, INT8 enforced, output is a directory). [dx-compiler@a087726ead v2.5.0: .deepx/memory/common_pitfalls.md#L251-L325] [dx-compiler@a087726ead v2.5.0: .deepx/memory/common_pitfalls.md#L945-L966]
- LayerNorm (ConvNeXt): supported only over last dim (`axis=-1`, Scale/B shape `[D]`, D < 4080, else CPU). Multi-dim `nn.LayerNorm([C, H, W])` unsupported. Decomposed ReduceMean/Sub/Pow/Sqrt/Div/Mul/Add supported when statistics are over a single dimension. [dx-compiler@a087726ead v2.5.0: source/docs/03_Building_Models.md#L49]
- Out-of-range opset from another framework: `onnx.version_converter.convert_version(model, 13)`. [dx-compiler@a087726ead v2.5.0: .deepx/memory/common_pitfalls.md#L107-L131]

### Compile (DX-COM)

- Never fabricate dx_com calls. Correct: `import dx_com` and `dx_com.compile(model=..., output_dir=...)`. Not existing: `dxcom.quantize()`, `dxcom.calibrate()`, `from dxcom import dxcom`, `model_path=`/`output=` kwargs, `target_device`/`output_format`/`model_path` config keys. Read `toolsets/dxcom-cli.md`, `dxcom-api.md`, `config-schema.md` before generating calls. [dx-compiler@a087726ead v2.5.0: .deepx/memory/common_pitfalls.md#L802-L834]
- Banned spellings: `output_path`, `model_path`, `calib_num`, `quant_device`; correct: `output_dir`, `model`, `calibration_num`. `SingleImageCalibDataset` and `CALIBRATION_OK` do not exist. [dx-all-suite@51d81fe2ef v2.5.0: .deepx/memory/sdk_grounding_reference.md#L107-L128]
- config.json `inputs` key must exactly match the ONNX input name (case and whitespace sensitive); shape must match exactly, batch 1, all dims positive. JSON config / `dxcom` CLI supports a single input only. [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/config-schema.md#L85-L95]
- `config=` and `dataloader=` are mutually exclusive in `dx_com.compile()`; with `dataloader=`, pass calibration settings as keyword arguments. `dataloader` batch size must be 1. No `dx_com.DataLoader`; use `torch.utils.data.DataLoader`. [dx-compiler@a087726ead v2.5.0: .deepx/memory/common_pitfalls.md#L921-L943] [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/dxcom-api.md#L51-L52] [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/dxcom-api.md#L88-L96]
- `quantization_device` deprecated in v2.5.0, ignored with a `UserWarning`. Use `--use_gpu {True,False}` / `use_gpu=` (default True = GPU when available, else CPU) and `CUDA_VISIBLE_DEVICES`. [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/config-schema.md#L229-L234] [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/dxcom-cli.md#L47-L52]
- Dev invocation: `--gen_log` and `--export_html`; review `<model>_summary.html` after every compile; `--verbose` expands masked errors; `--opt_level 0` for iteration, `--opt_level 1` (default) for final build. [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/dxcom-cli.md#L204-L212]
- Exit codes: only 0 = success is documented; do not rely on other codes. `DXCOM_LOG_LEVEL` is not a verified variable. [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/dxcom-cli.md#L186-L202]
- `--aggressive_partitioning` is experimental: maximises NPU ops, may increase compile time/memory or give unexpected results; use with `--gen_log`. Does not offload to CPU. [dx-compiler@a087726ead v2.5.0: .deepx/instructions/compilation-workflow.md#L203-L208] [dx-compiler@a087726ead v2.5.0: .deepx/skills/dx-agent-compiler-compile/SKILL.md#L639-L649]
- CLI is single-input only; multi-input needs the Python API with a DataLoader. Standalone `./dx_com/dx_com` is deprecated; use `dxcom` from the wheel (`pip install dx-com` in a venv). [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/dxcom-cli.md#L7-L31]
- Do not generate PPU type 2 (deprecated since v2.4.0). `ppu` and `pre_optimize` are mutually exclusive in one config; v2.5.0 does not reject the combination, it silently falls back (see debugging). PPU/`pre_optimize` are YOLO-detection only, irrelevant to a classifier. [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/config-schema.md#L267-L290] [dx-compiler@a087726ead v2.5.0: .deepx/skills/dx-agent-compiler-pre-optimize/SKILL.md#L132-L152]
- Never modify `compiler.properties` (since v2.5.0 only holds `COM_VERSION`; sourced as bash by `install.sh`). Fix compile failures in config.json, CLI args or the ONNX. [dx-compiler@a087726ead v2.5.0: .deepx/memory/common_pitfalls.md#L842-L890] (agent rule)
- QAT (`qmaster`) is opt-in: needs a GPU; mutually exclusive with `use_q_pro`/`enhanced_scheme` (`EnhancementSchemeError`); unknown `qmaster` keys silently ignored (check the Q-MASTER CONFIG box in compiler.log); `freeze_bn_after` must never be 0 (nan); removed args `qat_config`/`qat_resume_from_checkpoint` silently ignored. Run `fast_run` first; compare against PTQ on the same eval set. [dx-compiler@a087726ead v2.5.0: .deepx/memory/common_pitfalls.md#L998-L1012] [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/qat.md#L9-L10] [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/qat.md#L116-L118] [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/qat.md#L153] [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/qat.md#L257-L261]
- `--optimize_check` does not exist in the v2.5.0 CLI (argparse exit 2). [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/qat.md#L266]
- Accuracy escalation, one step at a time with re-measurement: calibration `ema` -> `minmax` -> `iqr`; then Q-PRO (`--use_q_pro` / `enhanced_scheme`, slow, opt-in); then `--quant_diagnosis` + QXNN `--checkpoint` resume; then QAT. [dx-compiler@a087726ead v2.5.0: .deepx/instructions/compilation-workflow.md#L168-L193]
- `--quant_diagnosis` writes `quant_diagnosis/diagnosis_report.html` and a `.qxnn` checkpoint; `--checkpoint x.qxnn -o out --recalibration_method iqr` re-quantizes without recompiling (resume-only flags error without `--checkpoint`). [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/dxcom-cli.md#L54-L68] [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/dxcom-cli.md#L157-L171]
- OOM during calibration: reduce `calibration_num` or quantize on CPU (`--use_gpu False`). [dx-compiler@a087726ead v2.5.0: .deepx/skills/dx-agent-compiler-compile/SKILL.md#L639-L649]
- Fresh working directory per session; keep onnx, config.json, .dxnn, compiler.log together; do not scan previous sessions for reusable ONNX/DXNN files. [dx-compiler@a087726ead v2.5.0: .deepx/memory/common_pitfalls.md#L189-L209] [dx-compiler@a087726ead v2.5.0: .deepx/memory/common_pitfalls.md#L516-L545] (agent rule)
- Long compiles: run in background with `start_new_session=True` and a `compile.pid`; poll with `kill -0 <PID>`, never `pgrep -f` (self-matching infinite loop). Agent file quotes 15-40 min, dominated by graph optimisation. [dx-compiler@a087726ead v2.5.0: .deepx/agents/dx-dxnn-compiler.md#L450-L513] [dx-compiler@a087726ead v2.5.0: .deepx/agents/dx-dxnn-compiler.md#L205-L212]
- Ubuntu 24.04+ enforces PEP 668; always create/activate a venv before `pip install`, never `--break-system-packages`. [dx-compiler@a087726ead v2.5.0: .deepx/memory/common_pitfalls.md#L549-L595] [dx-compiler@a087726ead v2.5.0: .deepx/memory/common_pitfalls.md#L714-L744]
- Compile can proceed where NPU init fails (dxcom runs on CPU), but NPU-based verification must be recorded as SKIPPED, not PASS. [dx-compiler@a087726ead v2.5.0: .deepx/memory/common_pitfalls.md#L909-L915]
- Wheels: `manylinux_2_31_x86_64` (glibc >= 2.31), Python 3.8-3.14; x86-64 only (no ARM64 dx_com). [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/dxcom-cli.md#L17-L18] [dx-compiler@a087726ead v2.5.0: .deepx/memory/common_pitfalls.md#L961-L962]

### Calibration

- Calibration images must be representative of inference data (not random/synthetic/other domain); avoid duplicates; include variety. [dx-compiler@a087726ead v2.5.0: .deepx/memory/common_pitfalls.md#L55-L74]
- Defaults: `calibration_method="ema"` (lowercase only; `"EMA"` rejected; alternatives `minmax`, `iqr`), `calibration_num=100`. Manual suggests trying 1, 5, 10, 100, 1000 and keeping the most accurate. Fewer images than `calibration_num`: all used, no warning. [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/config-schema.md#L105-L123]
- Real, multiple images from a directory is the official pattern; dataset class name is arbitrary; single-image augmentation is not the pattern. [dx-all-suite@51d81fe2ef v2.5.0: .deepx/memory/sdk_grounding_reference.md#L116-L121]
- `default_loader` reads with `cv2.imread` (BGR, HWC, uint8), applies `preprocessings` in order, never transposes. NCHW models (every PyTorch export incl. torchvision): end chain with `{"transpose": {"axis": [2, 0, 1]}}` then `{"expandDim": {"axis": 0}}`; keep final `expandDim` even for NHWC. Without it: `DataLoaderError: Invalid JSON Configuration for input ...`. [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/config-schema.md#L127-L142] [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/dxcom-cli.md#L214-L243]
- RGB models with mean/std on a [0,1] scale (e.g. ImageNet): put `convertColor BGR2RGB` and `div 255` before `normalize`. ImageNet mean `[0.485, 0.456, 0.406]`, std `[0.229, 0.224, 0.225]`. Use either the "Raw" std-255 row or `div 255`, not both. `normalize` is `(x - mean) / std`. [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/config-schema.md#L186-L219]
- Official YOLO preprocessing chain: `"preprocessings": [{"resize": {"width": 640, "height": 640}}, {"div": {"x": 255}}, {"convertColor": {"form": "BGR2RGB"}}, {"transpose": {"axis": [2, 0, 1]}}, {"expandDim": {"axis": 0}}]`. [dx-compiler@a087726ead v2.5.0: .deepx/memory/common_pitfalls.md#L644-L653]
- `resize` width/height should match the spatial dims of the `inputs` shape; `mode` is `default` (OpenCV) or `torchvision` (PIL), and interpolation names must come from the same mode. [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/config-schema.md#L193-L211]
- `file_extensions` is required and case-sensitive (list `"JPG"` too for uppercase files); subfolders are searched. [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/config-schema.md#L180-L187]
- `dataset_path` resolves relative to the directory where compile is called, not the config file. Prefer relative paths, or `os.path.abspath` when unsure; wrong path gives `DataNotFoundError`. [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/config-schema.md#L161-L177] [dx-compiler@a087726ead v2.5.0: .deepx/memory/common_pitfalls.md#L164-L185]
- Custom DataLoader route (multi-input, non-image, exotic preprocessing): return a CHW `float32` tensor from `__getitem__`; never `unsqueeze(0)` (gives `[1,1,C,H,W]`); `ToTensor()` scales to [0,1], so avoid it if the model expects 0-255; JSON `default_loader.preprocessings` is not used, so match inference preprocessing by hand. [dx-compiler@a087726ead v2.5.0: .deepx/memory/common_pitfalls.md#L660-L707] [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/dxcom-api.md#L224-L229]
- torchvision transforms kept in a Dataset `transform` attribute may be extracted and fused by DX-COM; hand-written preprocessing in `__getitem__` gives `Fused ops: (none)`. Always read the INPUT PREPROCESSING GUIDANCE block in compiler.log. [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/config-schema.md#L147-L158]
- The compiler may bake `normalize`/`subtract`/`div` (sometimes transpose) into the NPU graph. Every op on the `[INFO] - Added nodes:` line in compiler.log MUST be removed from host-side preprocessing, otherwise it is applied twice. [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/config-schema.md#L222-L228]
- QAT data: never train on the set used to report final accuracy. If `default_loader.dataset_path` is missing, v2.5.0 silently falls back to a built-in ImageNet location; verify the path exists. [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/qat.md#L221-L227]
- Agent-recommended sample set `dx_com/calibration_dataset/` (100 JPEG, downloaded from `https://sdk.deepx.ai/` by `example/2-download_sample_calibration_dataset.sh`); the agent notes it is generic and domain-specific data gives better accuracy. [dx-compiler@a087726ead v2.5.0: .deepx/instructions/compilation-workflow.md#L133-L147] [dx-compiler@a087726ead v2.5.0: .deepx/agents/dx-dxnn-compiler.md#L205-L233]

### Runtime (DX-RT / dx_engine)

- Compiled DXNN input can differ from ONNX (NHWC `[1,H,W,3]` uint8 vs NCHW float32) due to bake-in. Branch on `engine.get_input_tensors_info()` (`shape`, `dtype`); for NHWC do not extract H,W from `shape[2:]`. [dx_app@375de0344f v3.3.0: .deepx/memory/common_pitfalls.md#L444-L515] [dx-compiler@a087726ead v2.5.0: .deepx/memory/common_pitfalls.md#L748-L798]
- `verify.py`-style comparison: use the same preprocessing function for ONNX and DXNN paths (RGB/BGR, interpolation, 0-255 vs 0-1, padding). [dx-compiler@a087726ead v2.5.0: .deepx/memory/common_pitfalls.md#L458-L486]
- Compare ONNX and DXNN runs on the same sample (YOLO criteria: detection count within 20%, class labels, bbox IoU); never report success when this fails. [dx-compiler@a087726ead v2.5.0: .deepx/memory/common_pitfalls.md#L419-L438] (agent rule)
- Call names verified by dx_app against dx_engine source: `engine.run()` (not `infer`/`predict`); `get_input_tensors_info()[0]['shape']` (dict access, not `get_input_shape()` or dot access); `run_async()` returns `job_id`, `wait(job_id)` takes it; `Configuration().get_version()` (not `get_runtime_version()`); `DeviceStatus.get_device_count()` (not `list_devices()`); `dispose()` or context manager (not `close()`); `InferenceEngine(path)` constructor (not `load()`). `get_model_info()` does not exist; use `dxrt-cli --info model.dxnn`. [dx_app@375de0344f v3.3.0: .deepx/toolsets/dx-engine-api.md#L70-L110] [dx_app@375de0344f v3.3.0: .deepx/toolsets/dx-engine-api.md#L312-L330] [dx_app@375de0344f v3.3.0: .deepx/memory/platform_api.md#L358-L369]
- `InferenceOption` methods that exist: `set_use_ort`, `set_devices(list)`, `set_bound_option`, `set_buffer_count` (default 6, range 1-100); `option.devices = [0]` also works. Not existing: `set_device_id`, `set_num_threads`, `set_batch_size`, `set_profiling`, `set_log_level`; batch size is fixed at compile time. [dx_app@375de0344f v3.3.0: .deepx/memory/common_pitfalls.md#L655-L699] [dx_app@375de0344f v3.3.0: .deepx/memory/performance_patterns.md#L383-L399]
- Always release the engine (`with InferenceEngine(...) as engine:` or `dispose()`); abnormal termination (kill -9, segfault) can leave the NPU locked; recover with `dxrt-cli --reset`. Install a SIGINT handler in custom scripts so Ctrl+C does not leave a zombie holding the device. [dx_app@375de0344f v3.3.0: .deepx/memory/platform_api.md#L143-L160] [dx_app@375de0344f v3.3.0: .deepx/memory/common_pitfalls.md#L166-L193]
- DX-RT older than 3.0.0 silently returns all-zero outputs with no error (dx_app attributes it to `.dxnn` format v7 needing DX-RT >= 3.0.0); recompile `.dxnn` when upgrading DX-RT; check with `dxrt-cli -v` or `Configuration().get_version()`. [dx_app@375de0344f v3.3.0: .deepx/memory/common_pitfalls.md#L125-L148] [dx_app@375de0344f v3.3.0: .deepx/toolsets/dx-model-format.md#L120-L131]
- Sanity gate: run `bash scripts/sanity_check.sh --dx_rt` directly (no pipe to tail/head/grep); judge by output ("Sanity check PASSED!" and no `[ERROR]`), not exit code. If NPU "Device initialization failed", a cold boot is required; software install cannot fix it. This stop is unconditional, even if the user says continue. [dx-runtime@73ff9904f5 v2.5.0: .deepx/memory/common_pitfalls.md#L200-L215] [dx-runtime@73ff9904f5 v2.5.0: .deepx/memory/common_pitfalls.md#L230-L246] (agent rule)
- Build order: dx_rt first, then dx_app, then dx_stream; missing dx_rt shows as `cannot find -ldx_engine` or `gst-inspect-1.0 dxinfer` "No such element". [dx-runtime@73ff9904f5 v2.5.0: .deepx/memory/common_pitfalls.md#L176-L188]
- `run.sh` / `setup.sh` must use the same venv; `setup.sh` should fail hard (not warn) when `dx_engine` is not importable in the active venv. [dx_app@375de0344f v3.3.0: .deepx/memory/common_pitfalls.md#L746-L757]
- Headless hosts: guard `cv2.imshow` with a `DISPLAY`/`WAYLAND_DISPLAY` check; write images instead. [dx-runtime@73ff9904f5 v2.5.0: .deepx/memory/common_pitfalls.md#L101-L118]
- Model registry names are case-sensitive in `model_registry.json`. dx_app and dx_stream registries (`model_registry.json`, `model_list.json`) are independent and must be updated together. Not needed for our custom pipeline unless dx_app is adopted. [dx-runtime@73ff9904f5 v2.5.0: .deepx/memory/common_pitfalls.md#L9-L13] [dx-runtime@73ff9904f5 v2.5.0: .deepx/memory/common_pitfalls.md#L164-L172]
- Recovery/diagnostics commands listed by dx_app: `lsmod | grep dx_npu`, `ls -la /dev/dx_npu*`, `dmesg | grep dx_npu`, `dxrt-cli --diag`, `dxrt-cli -s`, `dxrt-cli --reset`. [dx_app@375de0344f v3.3.0: .deepx/memory/platform_api.md#L318-L336]

### Performance

- Biggest Python-level lever: SyncRunner -> AsyncRunner (5 worker threads + main thread, SafeQueue maxsize 4) overlaps CPU work and NPU inference; SyncRunner remains right for single-image/debugging. Numeric FPS ranges in the same file are agent estimates (see Hypotheses). [dx_app@375de0344f v3.3.0: .deepx/memory/performance_patterns.md#L29-L60]
- `engine.run_benchmark(num_loops=...)` for FPS; `get_latency()` / `get_npu_inference_time()` (microseconds) for latency; layer profiling via `Configuration().set_enable(Configuration.ITEM.PROFILER, True)` and `SHOW_PROFILE`. [dx_app@375de0344f v3.3.0: .deepx/memory/performance_patterns.md#L129-L175]
- Benchmark with `--no-display` to avoid display overhead. [dx_app@375de0344f v3.3.0: .deepx/memory/performance_patterns.md#L229-L235] [dx_app@375de0344f v3.3.0: .deepx/memory/performance_patterns.md#L366-L381]
- Compiler-skipped preprocessing ops (transpose, resize, expandDim) remain CPU MemoryOps on a single thread. Diagnose: `run_model -m model.dxnn -t 5 -v` vs the same with `--use-ort`; similar FPS = CPU-bound. Fix: `export DXRT_DYNAMIC_CPU_THREAD=ON`; look for `[DXRT] CPU TASK [cpu_0] ... Average Input Queue Load` above 50%. [dx_app@375de0344f v3.3.0: .deepx/memory/performance_patterns.md#L271-L333] [dx_app@375de0344f v3.3.0: .deepx/memory/common_pitfalls.md#L594-L653]
- Keep input uint8 when the model input is UINT8 (avoids float32 conversion); release frames promptly. [dx_app@375de0344f v3.3.0: .deepx/memory/performance_patterns.md#L334-L364]
- Choose a smaller/faster model rather than resizing a model away from its native resolution. [dx_app@375de0344f v3.3.0: .deepx/memory/performance_patterns.md#L100-L127]
- Compile-side knobs: `--opt_level 1` gives the lowest NPU latency; `--aggressive_partitioning` when too many ops stay on CPU; calibration/Q-PRO trade accuracy against compile time (Q-PRO P1-P5 "very slow", GPU gives 2-5x). [dx-compiler@a087726ead v2.5.0: .deepx/toolsets/dxcom-cli.md#L47-L52] [dx-compiler@a087726ead v2.5.0: .deepx/instructions/compilation-workflow.md#L168-L177]
- Web: DX-Benchmark offers reproducible NPU benchmark results, marked Beta. [developer.deepx.ai/tech-docs/, fetched 2026-11-05]

### Debugging

- Compile fails, checklist in order: `onnx.checker`, `inputs` key vs ONNX input name, batch 1, no dynamic dims, opset 11-21, calibration path exists with images, `--gen_log` and read compiler.log, `--aggressive_partitioning` for unsupported ops, single ONNX output, contact DEEPX with compiler.log. [dx-compiler@a087726ead v2.5.0: .deepx/instructions/compilation-workflow.md#L422-L436]
- `--verbose` / `verbose=True` expands masked errors (e.g. "Unknown error occurred during compilation. Please contact DEEPX." hid `ValueError: axes don't match array` for an NHWC model without the final `expandDim`).
