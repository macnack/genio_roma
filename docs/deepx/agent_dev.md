# DEEPX dx-agent-dev (`.deepx/`) system and reuse plan

Maps the official DEEPX "Agent-Driven Development" (dx-agent-dev, Beta) system found in dx-all-suite, dx-compiler, dx-runtime and dx_app, and gives a reuse plan for our PyTorch -> ONNX -> DX-COM -> DXNN -> DX-RT ConvNeXt-Tiny pipeline. Nothing here has been installed or executed; everything below describes what the sources say. Rules: [CONVENTIONS.md](CONVENTIONS.md). Related: [compiler.md](compiler.md), [runtime.md](runtime.md), [tricks_and_best_practices.md](tricks_and_best_practices.md), [README.md](README.md).

Abbreviations in citations: `dx-all-suite@51d81fe2ef v2.5.0`, `dx-compiler@a087726ead v2.5.0`, `dx-runtime@73ff9904f5 v2.5.0`, `dx_app@375de0344f v3.3.0`.

## Officially documented facts

### 1. What the system is

- `.deepx/` is the canonical source of truth. The `dx-agent-gen` generator (package `dx_agent_dev_gen`, in `.deepx/tools`) produces files for Claude Code, GitHub Copilot, Cursor, OpenCode, and (via `AGENTS.md` plus a Codex skill) Codex CLI. [dx-all-suite@51d81fe2ef v2.5.0: .deepx/docs/dx-agent-dev-overview.md#L8-L33] [dx-all-suite@51d81fe2ef v2.5.0: .deepx/docs/dx-agent-dev-overview.md#L65-L83]
- Repos with a `.deepx/`: dx-all-suite, dx-runtime, dx_app, dx_stream, dx-compiler. Directory roles: `agents/` (domain agents), `skills/` (procedural slash-commands), `templates/` (instruction-file templates; `fragments/` only at suite root), `memory/` (pitfalls, API grounding), `instructions/`, `knowledge/` (YAML), `toolsets/` (SDK API reference), `contextual-rules/`, `prompts/`, `scripts/`, plus suite-only `docs/`, `tools/`, `tests/`, `e2e/`. [dx-all-suite@51d81fe2ef v2.5.0: .deepx/docs/dx-agent-dev-overview.md#L85-L103]

### 2. Agents (definitions)

- Agent files are Markdown with YAML frontmatter: `name`, `description`, `argument-hint`, abstract `capabilities` (`read`, `edit`, `search`, `execute`, `sub-agent`, `ask-user`, `todo`) and `routes-to` (label, target, description). Example: `dx-compiler-builder` routes to `dx-model-converter` and `dx-dxnn-compiler`. [dx-compiler@a087726ead v2.5.0: .deepx/agents/dx-compiler-builder.md#L1-L20]
- Hierarchy: `dx-suite-builder` (top classifier) -> `dx-compiler-builder` -> `dx-model-converter` / `dx-dxnn-compiler`; and `dx-runtime-builder` -> `dx-app-builder` (-> python/cpp/benchmark/model-manager/validator) or `dx-stream-builder`. Validators: `dx-suite-validator`, `dx-validator` (runtime, dx_app, dx_stream). [dx-all-suite@51d81fe2ef v2.5.0: .deepx/docs/dx-agent-dev-overview.md#L35-L43]
- dx-compiler agents: `dx-compiler-builder` (router, 691 lines), `dx-model-converter` (PT -> ONNX, 247 lines), `dx-dxnn-compiler` (ONNX -> DXNN, 1235 lines). [dx-compiler@a087726ead v2.5.0: .deepx/agents/dx-compiler-builder.md#L1-L20] [dx-compiler@a087726ead v2.5.0: .deepx/agents/dx-model-converter.md#L1-L17] [dx-compiler@a087726ead v2.5.0: .deepx/agents/dx-dxnn-compiler.md#L104-L110]
- dx-runtime agents: `dx-runtime-builder` (router with Step 0 prerequisites gate, brainstorming gate, PPU routing) and `dx-validator` (5-step: identify scope, run validation, collect feedback, apply approved feedback, verify). [dx-runtime@73ff9904f5 v2.5.0: .deepx/agents/dx-runtime-builder.md#L1-L20] [dx-runtime@73ff9904f5 v2.5.0: .deepx/agents/dx-validator.md#L39-L117]

### 6. The compile / convert / validate workflow (dx-compiler)

- Router `dx-compiler-builder` loads context first (`.github/copilot-instructions.md`, `.deepx/memory/common_pitfalls.md`, `source/docs/` guides, `toolsets/*`) and classifies PT -> ONNX vs ONNX -> DXNN. [dx-compiler@a087726ead v2.5.0: .deepx/agents/dx-compiler-builder.md#L28-L42]
- Convert (`dx-model-converter` / `dx-agent-compiler-convert`): Phase 1 load model + `model.eval()`; Phase 2 `torch.onnx.export` with batch 1, `opset_version=13`, `dynamic_axes=None`; Phase 3 validate (`onnx.checker`, input shape, single output); Phase 4 simplify only on explicit request. The skill adds Phase 0 path selection (Ultralytics shortcut), Phase -1 model acquisition, Phase 0 working dir, Phase 2a Ultralytics handling. [dx-compiler@a087726ead v2.5.0: .deepx/agents/dx-model-converter.md#L29-L197] [dx-compiler@a087726ead v2.5.0: .deepx/skills/dx-agent-compiler-convert/SKILL.md#L16-L287]
- Compile (`dx-dxnn-compiler` / `dx-agent-compiler-compile`): Phase -1 dxcom installation pre-flight; Phase 0 working dir + calibration data (symlink); Phase 1 inspect ONNX; Phase 2 generate config.json; Phase 3 compile (background, `compile.pid`); Phase 4 PPU (detection only); Phase 5 validate output (`*_summary.html`, compiler.log); 5.5 mandatory artifacts (`setup.sh`, `run.sh`, `README.md`, `verify.py`, `session.log`); 5.6 TDD gate; 5.7 cross-validation with a precompiled reference model; 5.8 pre-DONE `.dxnn` existence check; Phase 6 final report. [dx-compiler@a087726ead v2.5.0: .deepx/agents/dx-dxnn-compiler.md#L109-L1033]
- Validate (`dx-agent-compiler-validate`): check output artifacts, inspect the compilation summary report, review compiler.log (errors, warnings, NPU vs CPU partition, quantization summary), optional cross-validation with a precompiled reference, report. Also documents QAT outputs. [dx-compiler@a087726ead v2.5.0: .deepx/skills/dx-agent-compiler-validate/SKILL.md#L21-L174]
- Runtime validation (`dx-agent-runtime-validate`): run validation, collect feedback proposals, review, apply approved fixes (dry run supported), re-validate. [dx-runtime@73ff9904f5 v2.5.0: .deepx/skills/dx-agent-runtime-validate/SKILL.md#L31-L52]
- The compiler agent must verify `dxcom` is installed (Phase -1), try `pip install dx-com` in a venv, then `dx-compiler/install.sh`, and stop if still missing. [dx-compiler@a087726ead v2.5.0: .deepx/agents/dx-dxnn-compiler.md#L111-L150]
- Cross-project suite tasks create two session directories (`dx-compiler/dx-agent-dev/<id>_compile/` and `dx-runtime/dx_app/dx-agent-dev/<id>_inference/`). [dx-all-suite@51d81fe2ef v2.5.0: .deepx/docs/dx-agent-dev-overview.md#L52-L54]

### 7. Risky instructions found in agent files (implication notes)

Each item is what the file literally instructs; the "implication" is ours.

- `dx-runtime-builder` Step 0 instructs running `bash install.sh --all --exclude-app --exclude-stream --skip-uninstall --venv-reuse` automatically when `sanity_check.sh --dx_rt` fails. [dx-runtime@73ff9904f5 v2.5.0: .deepx/agents/dx-runtime-builder.md#L56-L69] That `install.sh` uses `sudo` (e.g. `sudo ./build.sh -c install --reload`, and `sudo systemctl disable|stop|start|enable dxrt.service`). [dx-runtime@73ff9904f5 v2.5.0: install.sh#L88-L135] Implication: an agent following this changes the host kernel driver and system services; on our host (no DX-M1) it is not wanted. Do not let an agent auto-run it; keep installs manual.
- `dx-dxnn-compiler` Phase -1 and `dx-compiler-builder` fall back to `bash $COMPILER_DIR/install.sh` and `pip install dx-com`. [dx-compiler@a087726ead v2.5.0: .deepx/agents/dx-dxnn-compiler.md#L127-L141] `dx-compiler/install.sh` contains `sudo apt-get update`, `sudo env DEBIAN_FRONTEND=noninteractive apt-get install -y tzdata`, `sudo apt-get install -y python3 python3-venv python3-dev` (and `sudo dnf install` on another path). [dx-compiler@a087726ead v2.5.0: install.sh#L274-L276] [dx-compiler@a087726ead v2.5.0: install.sh#L321-L321] Implication: package installation with root; pre-install dx-com in our own venv so the fallback never triggers.
- The generated `setup.sh` template the agents must emit runs `dx-runtime/install.sh --all ...`, `dx-compiler/install.sh`, `pip install` of `dx_engine` wheel and `opencv-python numpy onnxruntime`. [dx-compiler@a087726ead v2.5.0: .deepx/instructions/compilation-workflow.md#L296-L335] Implication: the mandatory `setup.sh` is itself an install script; review before running.
- Calibration fallback downloads data with `example/2-download_sample_calibration_dataset.sh` from `https://sdk.deepx.ai/` (network fetch, executed by the agent); model acquisition phase may `wget` an arbitrary "official" URL or `pip install huggingface_hub`. [dx-compiler@a087726ead v2.5.0: .deepx/agents/dx-dxnn-compiler.md#L205-L233] [dx-compiler@a087726ead v2.5.0: example/2-download_sample_calibration_dataset.sh#L33-L33] [dx-compiler@a087726ead v2.5.0: .deepx/skills/dx-agent-compiler-compile/SKILL.md#L59-L96] Implication: untrusted-input fetches; also not representative ImageNet-quality data for ConvNeXt (see Hypotheses).
- The official E2E harness runs each CLI fully unattended: Claude Code with `-p --dangerously-skip-permissions`, Codex with `exec --json -s danger-full-access`, Copilot with `--yolo --no-ask-user`. [dx-all-suite@51d81fe2ef v2.5.0: .deepx/docs/dx-agent-dev-overview.md#L492-L498] Implication: these are test-harness settings; do not copy them into our daily workflow.
- Instruction fragments define an "autopilot" mode where ask-user prompts are replaced by knowledge-base defaults while all gates still apply. [dx-all-suite@51d81fe2ef v2.5.0: CLAUDE.md#L254-L254] [dx-all-suite@51d81fe2ef v2.5.0: CLAUDE.md#L363-L363] Implication: an agent may proceed without confirming choices such as calibration data or quantization options.
- Behavioural overrides imposed by the shipped `CLAUDE.md`: forced `/dx-skill-router` first on every message, `[DX-AGENT-DEV: START]` / `[DX-AGENT-DEV: DONE ...]` sentinel lines, model-notice banner for non-Sonnet/Opus 4.6+ models, `dx-agent-dev/<session_id>/` output isolation, "never `git add`/`git commit` under `docs/superpowers/`", and a ban on referencing previous sessions. [dx-all-suite@51d81fe2ef v2.5.0: CLAUDE.md#L13-L40] [dx-all-suite@51d81fe2ef v2.5.0: CLAUDE.md#L494-L494] [dx-all-suite@51d81fe2ef v2.5.0: CLAUDE.md#L1073-L1073] [dx-all-suite@51d81fe2ef v2.5.0: .deepx/docs/dx-agent-dev-overview.md#L56-L61] Implication: dropping `CLAUDE.md` into our project would alter all Claude sessions there, and could conflict with our own CLAUDE.md and `docs/` workflow.
- The pre-edit hook blocks edits (exit 2) to `.claude/agents|skills`, `CLAUDE.md`, `AGENTS.md` anywhere under a tree that contains `.deepx/`. [dx-all-suite@51d81fe2ef v2.5.0: .claude/hooks/pre-edit-generator-guard.sh#L38-L81] Implication: copying `.deepx/` plus the hook into our repo would make our own `CLAUDE.md` read-only for Claude.
- Agent rules say never reference prior sessions and always re-download/re-export/recompile from scratch, and `ls dx-agent-dev/` is prohibited. [dx-compiler@a087726ead v2.5.0: .deepx/memory/common_pitfalls.md#L516-L545] Implication: conflicts with caching ONNX/DXNN artifacts across our phases; our docs workflow must override explicitly.
